# Creo 插件开发 SKILLS

[English](README.md)

把 AI 连接 Creo 和 TOOLKIT 插件开发经验整理成可复用的工作流程：识别目标会话、独立 Ribbon、传统菜单、自动版本切换、真实按钮验证，以及功能提取与独立打包。

## 为什么做这套 SKILLS

最近在折腾 Creo 插件开发时，我越来越觉得：把需求告诉 AI，只是开始。

真正费时间的，往往是后面这些事情：

- 代码写出来了，能不能编译？
- DLL 生成了，Creo 能不能加载？
- 按钮出来了，中文和图标有没有显示正常？
- 自己电脑上能用，换一台电脑还能不能用？

这些问题反复遇到之后，我开始把开发流程、检查方法和踩过的坑整理成 **SKILL**，让后续开发有一套可以重复使用的做法。

我主要从 **Creo 12 及以上版本** 开始开发，下面也记录了旧版本 SDK 的来源与构建核验方法。

之前迭代过五百多次插件版本。AI 每优化一次，我还要回到 Creo：停止旧插件、移除旧注册、重新注册新版、启用插件，再关闭辅助应用程序窗口，才能继续测试。

一次次手动加载，真的很崩溃。所以，我把这段操作也整理进 SKILL，让 AI 在已授权的插件更新任务中，把版本切换和验证一起完成。

同一任务连续迭代时沿用已有授权，不必每次重新要求用户点击一遍。仅写文档、仅构建或明确要求手动注册的任务，不自动控制 Creo。

## 包含四类技能

| 类型 | 用途 | 界面 |
|---|---|---|
| [AI 连接 Creo](skills/creo-ai-connection/SKILL.md) | 通过 CREOSON/MCP 或原生异步 TOOLKIT 连接并核对目标会话 | 无需新增界面，先做只读检查 |
| 独立 Ribbon 工具栏 | 多功能、独立选项卡和分组 | 统一 16×16 图标＋中文名称，准备 32×32 配套资源 |
| 传统 Toolkit 菜单 | 小工具、诊断和少量命令 | 可以先只做中文文字菜单，不做图标 |
| 功能提取与独立打包 | 把指定功能做成可分享的独立插件 | 整理代码、资源、依赖和注册文件 |

## AI 怎样连接 Creo

新增的连接技能说明两条路径：已有的本机 CREOSON 服务通过 MCP 向 AI 提供工具；需要原生几何、事件或精确会话控制时，使用与目标版本匹配的异步 TOOLKIT/OTK 控制程序。先确认服务、目标 Creo 进程和活动模型，再执行只读查询。多个 Creo 同时运行而无法证明连接对象时，不修改或保存模型。技能压缩包只包含说明与参考资料；CREOSON、PTC SDK 和控制程序需按实际环境另行准备。

## 完整的版本切换

识别准确的 Creo 会话与目标插件 → 构建新文件名的 DLL → 停止旧插件 → 必要时移除已停止的旧注册条目 → 注册当前绝对路径的 DAT → 启动并核对新版 → 关闭辅助应用程序窗口 → 从实际按钮验证结果。

## 先验证算法，再验证真实按钮

算法阶段通过独立 TOOLKIT 测试程序连接真实 Creo，核对几何、尺寸、关联和再生结果。通过后再整合到正式插件，并从实际菜单或 Ribbon 按钮完整执行。

独立测试程序成功表示算法已验证；正式按钮得到预期结果，才表示插件功能已验证。独立分发包还要使用包内实际文件测试。只改菜单、资源或注册时，验证对应路径即可。

## 适用版本与安装

我从 Creo 12 及以上版本开始开发，打包技能也记录了旧版本 SDK 的来源、工具链和逐阶段验收。低版本 SDK 构建的插件可能在较新 Creo 中运行，但要分别在目标版本实测；不能只凭编译成功判断兼容。PTC SDK 归档仅保存在本机，不包含在这个仓库或 SKILLS 压缩包中。
