# Creo 插件功能提取与打包

将用户指定的现有功能做成独立、可复现构建、可注册的交付包。默认继承已验证的实现，不在打包过程中顺带重写 CAD 算法，也不把这次成功推广为所有模型都能处理。

普通主插件功能更新、修复和回归只处理主插件，不自动重建、测试或覆盖独立分发包。只有用户明确要求打包、导出独立插件或同步分发包时才执行；先前一次打包授权不代表每次修改都要重新打包。

## 算法先验证，整合后验证真实按钮

开发或修复 CAD 算法时，默认分为以下两个阶段。后文的 DLL 注册、切换和发布流程适用于整合阶段，不要求每次算法试验都重新注册插件。仅修改菜单、资源、注册或加载问题时，直接验证对应的插件入口，不强行增加独立算法试验。

1. **算法阶段**：优先用独立 TOOLKIT 测试程序连接明确识别的真实 Creo 测试会话，调用原生 API 或必要的原生命令，快速编译、运行和定位问题。这是真实 Creo 中的算法验证，不是离线模拟。使用用户授权的测试数据与修改范围，按任务要求核对几何、尺寸、关联及再生结果；记录测试程序/源码版本、Creo 版本、输入和结果。测试程序或模型操作失败时不能只凭进程退出码、宏返回成功判断功能完成。
2. **整合阶段**：算法通过后，将验证过的实现及必要依赖整合到正式插件或配套处理程序。尽量复用同一实现，移除诊断用硬编码路径和人工补救步骤；特别检查 DLL 回调与异步 TOOLKIT 的命令时序、会话连接、窗口切换及错误处理差异。构建最终版本并依照用户授权完成真实 DAT 注册/加载，从实际菜单或 Ribbon 按钮执行到最终结果，核对实际加载的 DLL、配套程序版本和业务验收指标。不能用直接调用 helper、编译成功、初始化成功或按钮出现代替完整命令验证。

独立测试程序成功仅表示“算法已验证”；真实按钮完整通过才表示“插件功能已验证”。若本次还要求独立包，必须用最终包内实际 DAT、DLL、处理程序和资源验证真实按钮，而不是复用开发目录的文件。未完成的阶段要明确标注，不宣称已交付可用。此流程不额外授权修改启动配置、关闭会话、保存模型或新增备份，也不要求每次算法修改都重新打包。

## 迭代时完成真实版本切换

当用户授权的插件更新任务包含注册、加载或运行测试时，按所选 Ribbon/传统菜单技能的版本切换流程完成：停止准确识别的旧插件，必要时移除已经停止的旧注册条目，注册当前绝对 DAT 路径，启动新版，关闭辅助应用程序窗口，再从实际按钮验证结果。沿用同一任务已经明确的授权，不让用户每次迭代重复手动操作。

这里移除的是旧注册条目，不是删除 DLL、源码或模型。没有旧条目时跳过停止和移除；不能安全卸载时说明具体阻碍，不强制关闭 Creo。只写文档、只构建或用户明确要求手动注册时，不自动控制运行中的会话。更新分发包仅限用户本次要求的范围。

## 范围和基线

- 从对话和实际文件确认命令范围、目标 Creo 版本、UI 形式和交付方式。信息足够就继续，不重复询问已确定的偏好。
- 对照正在使用的 DAT、DLL、源码、构建脚本和日志确定基线；不要凭最高版本号认定最新可用版本。DLL、源码和消息资源必须对应。
- 在独立项目冻结所需源文件及依赖，记录来源和哈希。不要默认从另一个仍在开发的主插件重新复制源码。
- 没有可重建源码时说明可做的范围；不能把整套 DLL 改名就声称完成了功能提取。

## Creo 跨版本兼容与构建基线

- 打包前确认接收者的 Creo 大版本及完整小版本，不能仅按开发电脑当前安装或打开的最高版本选择 SDK。
- 兼容是有方向的：较新 SDK 构建的 TOOLKIT 应用不支持在较旧 Creo 上运行；较旧 SDK 构建的应用通常可在较新 Creo 上运行，但跨大版本可能需要接口适配。依据：[PTC 版本兼容规则](https://support.ptc.com/help/creo_toolkit/protoolkit_pma/r12/usascii/creo_toolkit/user_guide/Version_Compatibility_Creo_ParametricCreo_and_Creo_Toolkit.html)。
- 当目标同时包含 Creo 12、13 时，优先尝试以最低目标版本（例如 Creo 12）的 SDK 作为共同基线，编译 DLL 及配套异步处理程序。检查实际使用的 API、结构体字段和运行库依赖；不能仅修改 DAT 描述、文件名或版本检查来绕过不兼容。
- 用同一套最终二进制分别在每个目标 Creo 版本验证真实 DAT 加载、命令入口和代表性模型的完整处理结果，并记录 DLL/处理程序哈希、SDK 版本、运行 Creo 完整版本及未通过项。加载成功不能代替功能通过；某一个版本测试通过不能推广到其他版本。
- 共同基线验证通过后优先交付一个包，避免无必要地长期维护 12、13 两套。只有已确认的接口或运行行为差异确实需要时才分版本；分版本时确保 DAT 指向匹配的 DLL 和处理程序。缺少目标环境时明确标注该版本未验证，不宣称通用兼容。
- 区分插件兼容与模型文件兼容：低版本 SDK 插件在高版本 Creo 中运行，不代表低版本 Creo 能读取高版本保存的原生模型；插件适配不能当作模型降版方案。

## 提取功能，而非整套启动行为

沿按钮 action → callback → 实现 → 辅助模块追踪实际依赖，包括消息、图标、对话框、配置、外部程序和输出目录。

- 新插件只注册指定动作与必要 UI。不要调用原套件整个 user_initialize，带入无关命令、自动保存、监听器、后台进程或原 Ribbon。
- 可复用成熟实现或冻结模块。若临时包含大源码文件并由链接器去除未引用代码，核对实际导出、链接依赖和初始化副作用；不要按源码体积宣称已独立。
- 检查遗留绝对路径、原作者盘符和安装目录。可写数据使用用户可写目录，不要求朋友电脑有 D 盘；保留模型备份、另存和错误处理语义。
- 少量命令通常适合原生 Toolkit 菜单；按用户要求选择 Ribbon。需要 UI 实现/注册细节时读现有 creo-toolkit-legacy-menu-plugin 或 creo-toolkit-ribbon-tab-plugin 技能，不无故改变既有 UI 合同。

## 独立命名和资源

- 给应用、action、菜单、按钮、消息文件及消息键分配独立命名空间。不能沿用原套件消息文件名，仅向其中追加新键；原文件可能已在会话中缓存。
- 消息文件名遵循目标 SDK 约束；当前已验证方案为短的小写 ASCII 名称和 .txt 后缀。应用及内部标识用 ASCII，显示语言按用户要求。
- 从一份权威消息源生成 text、text/chinese_cn、text/usascii 副本，逐个核对引用键和编码。已验证项目采用 UTF-8 BOM、四行 key/source/translation/# 记录。不要未经证实归因于 BOM 或盘符。
- 图标按 UI 技能部署并核对实际显示。每次构建生成的 DLL、消息、图标、DAT 和生成器必须指向同一发布版本。
- 若功能包含窗口切换、草绘编辑或原生交互宏，检查其在 DLL 回调和异步 TOOLKIT 中的执行差异。需要配套处理程序时，应一同冻结、构建、解锁、打包，并加入 DAT 生成器的必需文件检查；独立测试程序通过不能代替正式按钮验证。
- DLL 使用新版本文件名，不覆盖正在加载的文件。应用标识在命名空间迁移完成后保持稳定；不要每次修补都改变 Ribbon 所有者或堆积新菜单。

## 默认交付形态

没有另行要求时，可使用 ZIP + DLL + 完整 text + protk.dat + GenerateDAT.exe + 中文安装说明；不强制 EXE 安装器或 CMD/PowerShell。GenerateDAT 是小型注册文件生成工具，不是安装器。

1. 检查 DLL 的真实导入依赖和目标 SDK 兼容性，只打包需要且允许再分发的依赖。可附带官方 VC++ x64 运行库；不要复制 Creo 系统 DLL 作为跨版本修补。
2. 使用本机 PTC 正式工具及许可环境对需要分发的 Toolkit DLL 解锁并核验结果。解锁不等于数字签名，不绕过许可或安全提示。
3. DAT 使用绝对 exec_file 和 text_dir，包括 startup dll、allow_stop true、delay_start false 和独立末行 end；描述保持简短。
4. 便携包可采用已验证的全 ASCII 安装路径方案，提供默认 C:\<Folder> DAT，用原生生成器处理其他路径。不要把换到 C 盘当成资源错误的解决办法。若要求中文路径，单独验证，不承诺现有 ASCII 模板支持。
5. 使用 [DAT 生成工具说明](references/registration-helper.md) 和模板减少重复实现。生成器按自身目录生成、检查必需资源、备份不同内容的旧 DAT、原子替换且可重复运行；不改模型或全局配置。
6. 只有用户要求自动加载时才修改其已确认生效的 config.pro：备份后仅添加本插件加载项，不覆盖其他配置。手动注册包不需要改 config.pro。保留 Creo 安全提示。
7. 教程写清完整解压、路径、生成 DAT、注册/启动、实际菜单位置、升级旧条目、运行库安装条件和卸载方法。给朋友的包不含无关诊断 DLL、历史注册文件、模型或日志。

## 发布前验证

区分以下证据，不用一种替代另一种：

- **静态交付检查**：从最终 ZIP 解压，核对 DAT 路径、资源、引用键、位数、导出、依赖与 SHA256 清单。生成 DAT 后哈希改变是预期行为，不能沿用旧清单宣称逐字一致。
- 同步安装目录时先建立目标目录并保持相对目录结构，再校验所有文件；通配符复制命令返回成功不能证明 text 和 runtime 子目录完整。
- **生成器验证**：在隔离副本验证英文路径、带空格路径、重复运行、旧 DAT 备份、缺资源时不覆盖；当前模板对非 ASCII 路径应明确拒绝且不损坏原文件。测试实际编译出的 EXE。
- **真实加载验证**：使用最终包的真实 DAT，通过辅助应用程序注册/启动或真实 DAT 启动加载测试。核对实际 DLL 路径、版本及 command/designate/icon/menu/button 返回值，并看到入口。
- **命令验证**：在可恢复的模型副本执行指定按钮，核对该功能应产生的结果；重用先前算法验证时明确覆盖范围。菜单出现不等于 CAD 操作成功。

已授权的实际测试应继续完成；安全授权提示由用户亲自处理。无法完成运行验证时，明确具体未验证项，不宣称整包可用。

资源冲突修复至少覆盖干净会话及原工具已使用过的会话。失败时先读初始化阶段日志、DAT 实际指向与缓存情况，再缩小实验；不要仅换目录、改版本号后要求用户反复重试。

ProToolkitDllLoad 等程序接口仅辅助诊断，不能替代 DAT 验证，也不能据其结果单独判定包损坏。曾出现同一 DLL/资源通过接口加载报 -28，真实 DAT 全部成功的案例，见 [已验证案例](references/verified-case.md)。

隔离测试会话应记录归属，异步控制器应有明确的脱离/关闭设计。用户一旦在测试会话打开或编辑模型，就不能自动调用 ProEngineerEnd、超时关闭或杀会话；不要假设结束控制器一定不会影响 Creo。

交付时给一个明确的最终压缩包和本机 DAT 路径，说明实际验证到哪一步。保留可恢复的源码和旧包备份，避免用户从多份包中猜版本。
